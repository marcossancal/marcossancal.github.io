Como migrar um site WordPress sem perder o SEO que você construiu

Marcos Sanches · 30 de julho de 2026 · 8 min de leitura
Migração WordPress · SEO Técnico · Redirects · Search Console

Migração de site é uma das operações que mais assusta quem investiu anos construindo posicionamento no Google — e com razão. Feita de forma errada, uma migração pode derrubar rankings em horas e levar meses para recuperar. Feita corretamente, o Google processa a mudança em dias e o impacto no tráfego é mínimo.

A diferença entre os dois cenários está na preparação e nos detalhes técnicos. Este artigo é um checklist completo do que fazer antes, durante e depois de uma migração de WordPress — seja de servidor, de domínio, ou dos dois ao mesmo tempo.

Antes de qualquer coisa: nunca faça uma migração no horário de pico do seu site. Escolha uma madrugada ou um final de semana com menor tráfego. E avise sua equipe — mudanças de DNS afetam e-mail, integrações e outros serviços conectados ao domínio.

Entenda o que você está migrando

Existem três tipos de migração, e cada um tem implicações diferentes para o SEO:

  • Migração de servidor (mesmo domínio): você move os arquivos e o banco de dados para um novo hosting, mas o domínio não muda. É o tipo com menor risco para o SEO — as URLs continuam as mesmas, o Google não precisa reindexar nada.
  • Migração de domínio (novo endereço): você muda de site-antigo.com.br para site-novo.com.br. Todas as URLs mudam, todos os backlinks externos apontam para o domínio antigo, e o Google precisa entender que o conteúdo se moveu. É onde a maioria dos problemas de SEO acontece.
  • Migração de servidor + domínio: a combinação dos dois. Mais complexa, mais risco — mas com o processo correto, totalmente controlável.

O checklist abaixo cobre o cenário mais completo: mudança de servidor e de domínio. Se a sua migração for só de servidor, pule as partes que tratam de URLs e domínio.

Fase 1: antes de mover qualquer coisa

Faça um backup completo e verifique

Backup de arquivos e de banco de dados — os dois. E teste a restauração antes de começar. Um backup que não restaura não é um backup.

Documente o estado atual do SEO

Antes de mexer em qualquer coisa, registre onde você está. Isso vai ser a régua para medir o impacto depois:

  • Exporte o relatório de páginas indexadas do Google Search Console
  • Registre as posições médias das principais palavras-chave
  • Anote o tráfego orgânico dos últimos 30 dias no Google Analytics
  • Liste as 20–30 páginas com mais tráfego orgânico
  • Exporte todos os backlinks do Ahrefs, SEMrush ou Google Search Console

Mapeie todas as URLs que existem

Use o Screaming Frog (gratuito até 500 URLs) ou o sitemap atual para listar todas as URLs indexadas. Essa lista vai ser usada para criar os redirects.

Monte o mapa de redirects

Para cada URL antiga, defina a URL nova correspondente. Planilha mesmo — uma coluna com a URL de origem, outra com o destino. Toda URL que existe hoje e vai existir no novo site precisa ter um redirect 301 mapeado.

URLs que não vão existir no novo site precisam redirecionar para a página mais próxima tematicamente — nunca para a home por padrão. Mandar tudo para a home é um sinal negativo para o Google.

Fase 2: configuração do novo ambiente

Instale e configure o WordPress no novo servidor

Configure o site no novo servidor com um domínio temporário ou via arquivo hosts local para testar antes de apontar o DNS. Nunca virar o DNS antes de testar o site funcionando.

Migre os arquivos e o banco de dados

Ferramentas como o plugin Duplicator, All-in-One WP Migration ou rsync via SSH fazem isso bem. Após a migração, atualize as URLs no banco de dados com o WP-CLI:

wp search-replace 'https://dominio-antigo.com.br' 'https://dominio-novo.com.br' --all-tables

Rode isso duas vezes: uma para HTTP e outra para HTTPS, se o domínio antigo tinha os dois.

Configure os redirects 301 no servidor antigo

No .htaccess do servidor antigo (para Apache), com base no mapa de redirects que você montou:

RewriteEngine On
RewriteRule ^slug-antigo/?$ https://dominio-novo.com.br/slug-novo/ [R=301,L]

Para redirecionamento global de domínio (tudo do antigo para o novo, mantendo o caminho):

RewriteEngine On
RewriteCond %{HTTP_HOST} ^dominio-antigo\.com\.br$ [NC]
RewriteRule ^(.*)$ https://dominio-novo.com.br/$1 [R=301,L]

Se o servidor usa Nginx, a lógica é diferente — ajuste conforme a configuração do seu servidor.

Force HTTPS no novo site

Certifique-se de que o certificado SSL está instalado e que qualquer acesso via HTTP redireciona para HTTPS com 301. Mixed content (páginas HTTPS que carregam recursos via HTTP) também prejudica o SEO e a segurança.

Fase 3: verificações antes de virar o DNS

Com o site funcionando no novo servidor (via domínio temporário ou hosts), verifique item por item antes de apontar o DNS:

  • Todas as páginas carregam corretamente Teste as 20 páginas com mais tráfego — conteúdo, imagens, links internos
  • Formulários e funcionalidades funcionam Contato, checkout, login, busca — tudo que o usuário pode interagir
  • robots.txt não está bloqueando rastreamento Verifique se não há Disallow: / no robots.txt do novo servidor
  • Canonical tags apontam para as URLs corretas Cada página deve ter canonical apontando para si mesma no novo domínio
  • Sitemap atualizado com as novas URLs O sitemap.xml deve listar as URLs do novo domínio, não do antigo
  • Google Analytics e Search Console configurados Tags instaladas e propriedade verificada no novo domínio
  • Velocidade de carregamento aceitável Teste com PageSpeed Insights — problemas de performance no novo servidor afetam SEO

Fase 4: virando o DNS e as primeiras 48 horas

Reduza o TTL do DNS antes da migração

Com 24–48 horas de antecedência, reduza o TTL (Time to Live) do DNS para 300 segundos (5 minutos). Isso faz com que a propagação do DNS seja muito mais rápida na hora da virada — em vez de 24 horas, leva minutos.

Aponte o DNS e monitore

Aponte o domínio para o novo servidor. Confirme a propagação com ferramentas como dnschecker.org. Mantenha o servidor antigo ativo com os redirects configurados — ele vai receber tráfego enquanto o DNS ainda não propagou para todos os resolvedores.

Submeta o novo sitemap no Search Console

Acesse o Search Console do novo domínio e submeta o sitemap imediatamente após a virada. Isso acelera o rastreamento e a reindexação das novas URLs.

Notifique a mudança de endereço no Search Console

Se houve mudança de domínio, use a ferramenta "Mudança de endereço" no Search Console antigo (em Configurações). Isso instrui o Google a transferir os sinais de ranqueamento do domínio antigo para o novo de forma mais rápida.

Fase 5: monitoramento pós-migração

Nos primeiros 30 dias, acompanhe semanalmente:

  • Erros de rastreamento no Search Console: páginas retornando 404, erros de servidor, redirects chains (quando um redirect aponta para outro redirect, que aponta para outro)
  • Cobertura de índice: quantas páginas estão indexadas no novo domínio — deve crescer progressivamente
  • Tráfego orgânico no Analytics: comparando com o período equivalente antes da migração
  • Posições das principais palavras-chave: usando o Search Console ou uma ferramenta de monitoramento
Queda temporária é normal. Nos primeiros 7 a 14 dias após uma migração com mudança de domínio, alguma queda de tráfego é esperada — o Google está processando os redirects e reindexando as novas URLs. Se a queda persistir além de 4 semanas, investigue os redirects, os canonicals e o robots.txt.

Os erros mais comuns que prejudicam o SEO na migração

  • Usar redirect 302 em vez de 301: o 302 é temporário — o Google não transfere autoridade e continua indexando a URL antiga.
  • Redirect chains: URL A redireciona para URL B que redireciona para URL C. Cada salto dilui a autoridade. O redirect deve ir direto do origem ao destino final.
  • Derrubar o servidor antigo antes da propagação completa: visitas vindas de links externos ou de buscas ainda não atualizadas vão para um servidor que não existe.
  • robots.txt bloqueando rastreamento por engano: acontece quando o arquivo do ambiente de desenvolvimento (que bloqueia tudo para não ser indexado) vai para produção sem ser revisado.
  • Sitemap com URLs antigas: submeter o sitemap do domínio antigo no Search Console do novo domínio confunde o Google sobre qual URL deve ser indexada.
  • Canonical apontando para o domínio errado: se o plugin de SEO não foi atualizado após o search-replace no banco, os canonicals podem ainda apontar para o domínio antigo.

Perguntas frequentes

Depende do tamanho do site e da autoridade do domínio. Sites pequenos com bom histórico costumam ser reindexados em dias. Sites grandes podem levar semanas. O que acelera o processo é submeter o sitemap atualizado no Search Console logo após a migração, usar a ferramenta de inspeção de URL para solicitar reindexação das páginas mais importantes, e garantir que os redirects 301 estejam todos corretos — eles passam a autoridade das URLs antigas para as novas.
301 sempre, em migrações. O 301 é permanente e instrui o Google a transferir a autoridade da URL antiga para a nova. O 302 é temporário — o Google não transfere autoridade e continua indexando a URL original. Usar 302 em uma migração é um dos erros que mais prejudica o SEO.
Sim, por pelo menos 30 dias. Enquanto o Google ainda não reindexou todas as páginas nas novas URLs, manter o servidor antigo com os redirects 301 configurados garante que qualquer visita vinda de um link externo ou de uma busca ainda não atualizada chegue ao destino certo. Derrubar o servidor antigo antes disso pode gerar 404 em páginas que ainda não foram reindexadas.
Queda temporária de ranking nos primeiros 7 a 14 dias depois da migração é normal — o Google está processando as mudanças. Se a queda persistir além de 3 a 4 semanas, verifique: se todos os redirects estão respondendo com 301 (não 302 ou redirect chains), se o canonical das novas URLs aponta para si mesmo, se o robots.txt não está bloqueando rastreamento por engano, e se o sitemap submetido no Search Console contém as novas URLs. A maioria dos problemas persistentes de SEO pós-migração tem origem em uma dessas quatro causas.

Vai migrar um site e não quer perder o ranking?

Me chama antes de mexer em qualquer coisa. Com o checklist certo e a execução correta, a migração não precisa custar nada em SEO.
